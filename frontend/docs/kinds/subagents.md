# Субагенты и пользовательские команды

## Субагенты

Субагент — описание отдельного ИИ-помощника с ролью и набором инструментов: файл `*.md` в `~/.agents/agents/` в формате agents.

```markdown
---
name: reviewer
description: Читает код и находит ошибки.
tools: [read, grep]
claude:
  model: opus
---

Ты — ревьюер…
```

- Ядро: `name`, `description`, `tools` и тело — инструкция.
- `tools` — список инструментов [словаря agents](./hooks.md#словарь) или `"*"`. Без `tools` субагенту доступны все инструменты. Запись через запятую (`tools: read, grep`) тоже читается.
- Раздел расширений — ключ с именем ИИ-агента из [каталога](../reference/catalog.md) (`claude:`, `grok:`…). Его поля (`model`, `permissionMode`, `effort` и другие) получает только этот ИИ-агент: `on` поднимает их на верхний уровень frontmatter.
- Поле вне ядра и вне раздела расширений (например, `model:` на верхнем уровне) и инструмент не из словаря — отказ подключения. Пояснение называет файл и поле.

| ИИ-агент | Место | Инструменты |
|---|---|---|
| Claude Code | `~/.claude/agents/<имя>.md` | `tools: Read, Grep` |
| Grok Build | `~/.grok/agents/<имя>.md` | список имён Grok |
| Gemini CLI | `~/.gemini/agents/<имя>.md` | список имён Gemini |
| GitHub Copilot | `~/.copilot/agents/<имя>.agent.md` | `execute`, `read`, `edit`, `search`, `web`, `agent` |
| Cursor | `~/.cursor/agents/<имя>.md` | только `readonly` |
| Codex | `~/.codex/agents/<имя>.toml` | только `sandbox_mode` |
| Остальные | пропускают вид «субагенты» | |

Файл, которому перевод не нужен (без `tools` и без разделов расширений), ИИ-агент с форматом `*.md` получает ссылкой: правка в `~/.agents` видна сразу. Остальные файлы `on` переводит и пишет как свои записи. Повторный `on` обновляет их, `off` удаляет.

### Инструменты, которых у ИИ-агента нет

- Инструмент, которого у ИИ-агента нет, выпадает только у него, и вывод `on` его называет: `инструменты субагентов web_search`.
- Если после этого у субагента не осталось ни одного инструмента, этот ИИ-агент его не получает: `субагенты writer`. Пустой список никогда не значит «все инструменты».

### Cursor и Codex

У Cursor и Codex нет списка инструментов субагента.

- Субагент без `tools` приходит без ограничения.
- Субагент, у которого все инструменты только читают (`read`, `glob`, `grep`, `list`, `web_fetch`, `web_search`), получает `readonly: true` у Cursor и `sandbox_mode = "read-only"` у Codex.
- Остальные субагенты с `tools` этим двум ИИ-агентам не достаются: иначе ограниченный субагент получил бы все инструменты.

Codex получает TOML: `name`, `description`, `developer_instructions` — тело файла, и скалярные поля раздела `codex:`.

## Пользовательские команды

Пользовательская команда — файл `*.md` с текстом запроса, который ИИ-агент запускает по имени `/имя`.

```markdown
---
description: Проверить изменение
argument-hint: <файл>
---

Проверь $ARGUMENTS и назови ошибки.
```

Ядро: `description`, `argument-hint` и тело с `$ARGUMENTS` и `$1…$9`. Расширения — как у субагентов.

| ИИ-агент | Место |
|---|---|
| Claude Code | `~/.claude/commands/<имя>.md` |
| Gemini CLI | `~/.gemini/commands/<имя>.toml`: `description` и `prompt`, где `$ARGUMENTS` заменён на `{{args}}` |
| Grok Build | читает `~/.agents/commands` сам, `on` ничего не пишет |
| Остальные | пропускают вид «пользовательские команды» |

Команда с `$1…$9` к Gemini CLI не приходит: у Gemini нет нумерованных аргументов. Вывод `on` её называет: `пользовательские команды pick`.

## Публикация

Публикация ИИ-агента несёт вместо переведённого файла исходный файл `~/.agents`. При применении в `~/.agents` ложится он, а не перевод.

## Общие правила

- Собственные файлы ИИ-агента с другими именами остаются у него.
- Одноимённый собственный файл уходит в снимок ИИ-агента, затем на его месте появляется ссылка или переведённый файл.
- Повторный `on` убирает ссылку или переведённый файл элемента, которого в `~/.agents` больше нет.
