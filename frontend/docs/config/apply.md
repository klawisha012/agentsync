# Применение

Применение — разовое действие, которое переносит публикацию на вашу машину. Поздние публикации автора сами на машину не приходят: для них нужно новое применение.

```sh
agentsync apply Author claude
```

`Author` — имя автора на сайте, `claude` — имя карточки. Команду применения можно скопировать на странице публикации.

## Публикация ИИ-агента

Публикация ИИ-агента идёт через `~/.agents`:

1. **Элементы agents** из публикации — навыки, субагенты, пользовательские команды, файл инструкций, записи MCP, плагинов и хуков — ложатся в `~/.agents`. Одноимённый элемент заменяется целиком, новый добавляется, остальные элементы `~/.agents` остаются.
2. **Собственные файлы ИИ-агента** (`settings.json`, `keybindings.json` и другие) ложатся в его домашнюю папку по тому же правилу: одноимённый файл заменяется целиком, остальные остаются.
3. **Подключение.** Затем ИИ-агент подключается к `~/.agents`, как после `agentsync <ии-агент> on`.

Элемент agents узнаётся по месту, которое называет [каталог ИИ-агентов]: например, `skills/` и `CLAUDE.md` у Claude Code. Записи MCP, плагинов и хуков, которые на машине автора вписал `on`, публикация отмечает отдельно, и они тоже идут в `~/.agents`.

[каталог ИИ-агентов]: ../reference/catalog.md

::: warning settings.json заменяется целиком
Личные ключи `settings.json` применяющего (например, `statusLine` и разрешения) уходят в снимок перед применением. Машинные хуки при этом остаются.
:::

### Старые публикации

Публикации, загруженные до появления `~/.agents`, разбираются по тем же местам каталога. Все их записи MCP и плагинов идут в `~/.agents`. Пример для Claude Code: навыки, `CLAUDE.md` и все записи MCP уходят в `~/.agents`, остальное — в `~/.claude`.

Хуки, которые вписал `on`, ложатся в `~/.agents` той записью agents, из которой пришли. Если публикация этого не помнит (она старше формата agents), хук переводится обратно в формат agents с `"input"` ИИ-агента-источника. Хук, который словарь agents не выражает, ложится в раздел расширений этого ИИ-агента.

## Публикация agents

```sh
agentsync apply Author agents
```

Публикация `agents` точно заменяет `~/.agents`: элемент, которого в публикации нет, уходит из `~/.agents` и остаётся в снимке. Файл `~/.agents/.env` и машинные MCP-серверы остаются. После применения подключённые ИИ-агенты подключаются заново.

Если `hooks.json` публикации в старом формате (без `"version": 1`), применение отказывает и `~/.agents` не меняется: `Хуки в ~/.agents/hooks.json в старом формате…`.

::: danger Это заменяет общую настройку всех ИИ-агентов
Применение чужой публикации `agents` меняет то, что видят все подключённые ИИ-агенты машины. Вернуть прежний `~/.agents` можно командой `agentsync revert agents`.
:::

## Что сохраняется

Применение не трогает:

- учётные данные ИИ-агента (вход в сам ИИ-агент);
- машинные MCP-серверы и машинные хуки этой машины;
- файлы программы ИИ-агента и их кэши;
- `~/.agents/.env`.

## Снимки перед применением

Перед изменением `~/.agents` и переносимая настройка ИИ-агента записываются снимками в свои хранилища. Откат:

```sh
agentsync revert claude
agentsync revert agents
```

## Обрыв

Если применение обрывается, файлы `~/.agents` и домашней папки возвращаются к состоянию до попытки, снимок попытки в хранилище не попадает, а CLI печатает пояснение.

## Своя публикация

Свою публикацию применяют только с сессией этого аккаунта (`agentsync login`). Чужую открытую публикацию применяют без входа. Скрытую чужую публикацию применить нельзя: команда печатает пояснение.

## Команда со страницы сайта

Страница публикации показывает команду применения и команду отката. Кнопка «Скопировать» кладёт их в буфер обмена, затем выполните их в терминале. Если автор закрыл копирование команды в [настройках приватности](../site/privacy.md), команды применения на странице нет.
