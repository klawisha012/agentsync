# agents и подключение

`~/.agents` — общая настройка всех ИИ-агентов машины. Навык, правило или MCP-сервер вы описываете один раз, а каждый подключённый ИИ-агент видит его на своём обычном месте.

## Что лежит в `~/.agents`

У каждого вида элементов один формат — формат Claude Code.

| Путь | Вид | Страница |
|---|---|---|
| `skills/<навык>/SKILL.md` | навыки | [Навыки](../kinds/skills.md) |
| `agents/*.md` | субагенты | [Субагенты и команды](../kinds/subagents.md) |
| `commands/*.md` | пользовательские команды | [Субагенты и команды](../kinds/subagents.md) |
| `AGENTS.md` | файл инструкций | [Файл инструкций](../kinds/instructions.md) |
| `mcp.json` | MCP-серверы | [MCP-серверы](../kinds/mcp.md) |
| `plugins.json` | записи плагинов | [Плагины](../kinds/plugins.md) |
| `hooks.json` | хуки | [Хуки](../kinds/hooks.md) |
| `.env` | значения секретов | [MCP-серверы](../kinds/mcp.md#переменные-секрета) |

## Подключение

```sh
agentsync claude on
```

Имя ИИ-агента — имя из [каталога ИИ-агентов](../reference/catalog.md) или его синоним: `claude` и `claude-code` называют одну программу. Аккаунт, вход и сервер не нужны: подключение работает без сети.

Каждый вид элементов ИИ-агент получает одним из двух способов:

- **Ссылкой** — навыки, субагенты, пользовательские команды, файл инструкций. Правка в `~/.agents` сразу видна ИИ-агенту, повторять `on` не нужно.
- **Переводом** — MCP-серверы, плагины, хуки. Они лежат в общем файле настроек ИИ-агента рядом с его собственными записями, поэтому `on` вписывает их в формате ИИ-агента. Машина помнит, какие записи вписала она. Изменения этих видов доходят до ИИ-агента после повторного `on`.

Вид, который ИИ-агент не понимает, пропускается. Это не отказ.

### Вывод

```text
ИИ-агент codex видит из agents: пользовательские команды, файл инструкций, MCP-серверы.
Пропущены виды, которых ИИ-агент не понимает: субагенты, плагины.
```

Если переменной секрета нет ни в окружении, ни в `~/.agents/.env`, а ИИ-агент её не раскрывает, вывод называет и её:

```text
Переменные секрета вписаны как есть, их значения нет в окружении и ~/.agents/.env: GITHUB_TOKEN.
```

### Что получает каждый ИИ-агент

| Вид | Claude Code | Codex | Gemini CLI | Остальные |
|---|---|---|---|---|
| Навыки | `~/.claude/skills` | `~/.codex/skills` | `~/.gemini/skills` | свой каталог навыков |
| Субагенты | `~/.claude/agents` | — | — | — |
| Команды | `~/.claude/commands` | `~/.codex/prompts` | — | — |
| Файл инструкций | `~/.claude/CLAUDE.md` | `~/.codex/AGENTS.md` | `~/.gemini/GEMINI.md` | — |
| MCP-серверы | `~/.claude.json` | `~/.codex/config.toml` | `~/.gemini/settings.json` | — |
| Плагины | `~/.claude/settings.json` | — | — | — |
| Хуки | `~/.claude/settings.json` | — | `~/.gemini/settings.json`, с переводом событий | — |

`CLAUDE_CONFIG_DIR` и `CODEX_HOME` переносят домашнюю папку Claude Code и Codex; подключение их учитывает. Полный список ИИ-агентов и их каталогов: [Каталог ИИ-агентов](../reference/catalog.md).

### Занятое имя

Если у ИИ-агента уже есть собственная папка или файл с именем элемента `~/.agents` (например, свой `CLAUDE.md` или навык `grill-me`), `on` сначала создаёт снимок ИИ-агента в его хранилище и переносит туда эту папку целиком, затем ставит ссылку. Прежнюю папку возвращает `agentsync revert <ии-агент>`.

Собственные элементы ИИ-агента с другими именами остаются у него и в `~/.agents` не переходят.

### Повторное подключение

Повторный `on` синхронизирует ИИ-агента с текущим `~/.agents`:

- убирает ссылку на элемент, которого в `~/.agents` больше нет;
- убирает свою запись MCP, плагина или хука, которой в `~/.agents` больше нет;
- вписывает новые записи.

Одноимённую чужую запись MCP, плагина или хука `on` заменяет и запоминает прежнюю. `off` её возвращает.

## Отключение

```sh
agentsync claude off
```

- Ссылки на `~/.agents` уходят из всех мест ИИ-агента, в том числе ссылки на удалённые элементы.
- Из файлов настроек уходят только записи, которые вписал `on`. Заменённые чужие записи возвращаются.
- Собственные файлы ИИ-агента и сам `~/.agents` остаются.
- Папка, которую положила [установка навыка](./skills.md), остаётся.
- Без ссылок и своих записей команда ничего не меняет и не падает.

Собственный файл, который `on` убрал в снимок ради ссылки, возвращает `agentsync revert <ии-агент>`.

## Отказ подключения

Эти причины проверяются до изменения файлов, поэтому при отказе домашняя папка ИИ-агента не меняется.

| Пояснение | Что сделать |
|---|---|
| `В agents нечего показать.` | Положите в `~/.agents` хотя бы один элемент. |
| `ИИ-агента «…» нет в каталоге ИИ-агентов.` | Проверьте имя по [каталогу](../reference/catalog.md). |
| Два навыка с одним именем папки | Переименуйте одну из папок в `~/.agents/skills`. |
| `Секрет в файле <путь>.` | Замените значение переменной секрета `${NAME}`. |
| `Система не разрешила создать ссылку…` | На Windows включите режим разработчика (Параметры → Для разработчиков) или запустите команду от администратора. |

Если подключение обрывается на середине, оно возвращает домашнюю папку ИИ-агента к состоянию до попытки.

## ИИ-агенты, которые читают `~/.agents` сами

Cline, Warp, Zed, Droid и ещё несколько ИИ-агентов читают навыки прямо из `~/.agents/skills`. Для них `on` навыки не трогает, а `off` отказывает: отключить их нельзя.

## Публикация и откат `~/.agents`

```sh
agentsync record agents
agentsync push agents
agentsync revert agents
```

`~/.agents` — такая же карточка, как ИИ-агент, с именем `agents`. Снимок не берёт `~/.agents/.env`. Применение публикации `agents` точно заменяет `~/.agents`: подробно в [Применение](./apply.md#публикация-agents).
