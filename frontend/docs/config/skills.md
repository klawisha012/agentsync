# Отдельные элементы

`agentsync apply` с номером версии и путями кладёт в `~/.agents` только названные элементы одной версии публикации `agents`. Остальная настройка не меняется.

```sh
agentsync apply Author --version 4 skills/ru-text agents/reviewer.md AGENTS.md
```

| Часть | Значение |
|---|---|
| `Author` | автор публикации |
| `--version 4` | номер опубликованной версии `agents` |
| `skills/ru-text …` | пути файлов и папок версии, как в дереве на странице версии; каждый отдельным аргументом |

## Как ложатся элементы

- Папка с `SKILL.md` ложится в `~/.agents/skills/<имя>`, где бы она ни лежала в версии: `plugins/p/skills/deep` станет `skills/deep`.
- Субагенты, пользовательские команды и `AGENTS.md` ложатся на свои места в `~/.agents`. Записи MCP, плагинов и хуков вписываются в `mcp.json`, `plugins.json` и `hooks.json` каталога `~/.agents`.
- Одноимённый элемент заменяется целиком, остальные элементы `~/.agents` остаются.
- Две выбранные папки навыков с одним именем команду останавливают, и файлы не пишутся.
- Перед записью `~/.agents` уходит в локальный снимок: `agentsync revert agents` его возвращает. Затем подключённые ИИ-агенты подключаются заново.

## Доступ

- Открытую версию команда берёт без входа.
- Скрытую версию берёт только владелец: с сессией своего аккаунта (`AGENTSYNC_COOKIE` или `agentsync login`) или с токеном своей машины (`AGENTSYNC_TOKEN`).

## Элементы со страницы версии

На странице версии публикации включите «Выделение» и отметьте навыки, папки и файлы. Сайт соберёт готовую команду `agentsync apply` для всех отмеченных элементов.

## Элементы для всех ИИ-агентов сразу

Всё, что лежит в `~/.agents`, видят подключённые ИИ-агенты: [agents и подключение](./agents.md).
