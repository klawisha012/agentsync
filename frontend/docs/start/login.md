# Вход и машина

## Вход

```sh
agentsync login
agentsync login alice@example.com
```

Команда спрашивает почту (если вы её не указали) и пароль. Сессия пишется в `~/.agentsync/session`, имя аккаунта — в `~/.agentsync/account`. Пароль на диск не записывается.

::: danger Не публикуйте файл сессии
`~/.agentsync/session` открывает ваш аккаунт. Не кладите его в репозиторий и не передавайте другим.
:::

### Что работает без входа

| Действие | Нужен вход |
|---|---|
| `help`, `version`, `update` | нет |
| `agentsync <ии-агент> on` и `off` | нет |
| `revert` | нет |
| `skills` для открытой версии | нет |
| `apply` чужой открытой публикации | нет |
| `push`, `all`, `record`, `store` | да |
| `apply` своей публикации | да, сессия этого аккаунта |

Подтверждать почту для публикации не нужно. Ни одно действие сервиса не требует подтверждённой почты.

## Подтверждение машины

Подтверждение машины связывает локальный агент компьютера с вашим аккаунтом. После него локальный агент выполняет кнопки сайта — применение и откат — на этом компьютере.

- У компьютера один аккаунт за раз. Новое подтверждение сменяет прежнее.
- Копия хранилища прежнего аккаунта остаётся на диске, новому аккаунту она не показывается.
- Подтверждённые машины видны владельцу на [странице аккаунта](../site/account.md).

### Снятие подтверждения

Владелец снимает подтверждение машины на странице аккаунта. Локальный агент этой машины перестаёт входить в аккаунт. Хранилище аккаунта остаётся.

## Своя и чужая публикация

Свою публикацию применяют только с сессией этого аккаунта: в CLI после `agentsync login`, на сайте — после входа в браузере. Без сессии команда останавливается с пояснением. Чужую открытую публикацию применяют без входа.
