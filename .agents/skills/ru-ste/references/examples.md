# Примеры применения Ru-STE

В этом файле приведены практические сценарии преобразования неструктурированного или двусмысленного русского текста в форму Ru-STE для надежного парсинга AI-агентами.

---

## 1. Описание инструмента (Tool Description для LLM/MCP)

### Исходный текст (Многозначный, пассивный, с нанизыванием падежей)
> «Данный инструмент предназначен для реализации возможности выполнения операций по поиску и извлечению информации из базы данных пользователей при условии передачи валидного идентификатора сессии и параметров фильтрации, которые могут быть опциональными.»

### Преобразование по правилам Ru-STE
> «Поиск записей пользователей в базе данных.
> Инструмент принимает два аргумента:
> 1. `session_id` (обязательный) — строка с идентификатором текущей сессии.
> 2. `filter` (опциональный) — объект с критериями фильтрации.
> Инструмент возвращает массив найденных объектов или пустой массив, если записи не найдены.»

---

## 2. Системная инструкция для субагента (Prompt / Handoff)

### Исходный текст (Длинные предложения, пассив, модальная неопределенность)
> «Перед тем как производить какие-либо модификации в исходном коде, агенту следует осуществить предварительный анализ архитектуры проекта и убедиться в отсутствии конфликтов с существующими модулями, после чего можно приступать к написанию тестов, которые должны быть запущены и успешно пройдены.»

### Преобразование по правилам Ru-STE
> «Выполняйте шаги в строгом порядке:
> 1. Проанализируйте архитектуру проекта перед изменением кода.
> 2. Проверьте совместимость изменений с существующими модулями.
> 3. Напишите модульные тесты для новой функциональности.
> 4. Запустите тесты. Все тесты должны завершиться успешно.
> 5. Начните изменение исходного кода только после прохождения тестов.»

---

## 3. Сообщение об ошибке (Error Message / Diagnostics)

### Исходный текст (Расщепленные сказуемые, местоименная путаница)
> «Произошла ошибка в процессе выполнения операции сохранения файла конфигурации сервисом ввиду того, что он заблокирован другим процессом.»

### Преобразование по правилам Ru-STE
> «Ошибка сохранения конфигурации. Сервис не может записать файл `config.yaml`. Файл заблокирован внешним процессом. Завершите блокирующий процесс и повторите сохранение.»

---

## 4. Регламент и процедура (Runbook / SOP)

### Исходный текст (Сложноподчиненные предложения, отсутствие субъекта)
> «Для осуществления обновления базы данных необходимо остановить веб-сервер, затем сделать резервную копию таблиц, после чего применить миграции и, в случае успешного их выполнения, запустить сервер обратно.»

### Преобразование по правилам Ru-STE
> «Процедура обновления базы данных:
> 1. Остановите веб-сервер командой `systemctl stop app`.
> 2. Создайте резервную копию базы данных командой `pg_dump db > backup.sql`.
> 3. Примените миграции командой `migrate up`.
> 4. Если миграция завершилась с ошибкой, восстановите базу из резервной копии и не запускайте сервер.
> 5. Если миграция завершилась успешно, запустите веб-сервер командой `systemctl start app`.»
