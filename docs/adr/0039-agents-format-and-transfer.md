# Формат agents не принадлежит ни одному ИИ-агенту, собственные элементы переходят в agents при снимке

Формат agents раньше был форматом Claude Code (ADR 0037). Теперь у формата agents нет хозяина: каждый ИИ-агент, Claude Code тоже, получает элемент ссылкой, если формат совпадает с его собственным, или переводом. Где у вида есть открытый стандарт, формат agents — этот стандарт: `SKILL.md` у навыка, `AGENTS.md` у файла инструкций, `mcpServers` с полями `command`, `args`, `env`, `url`, `headers`, `type`, `disabled` у MCP. Плагины остаются как были: это вид с одним получателем. Для хуков, субагентов и пользовательских команд формат свой: общее ядро и разделы расширений.

Ядро строится по правилу: слово входит в ядро, если его понимают хотя бы два ИИ-агента. Остальное уходит в раздел расширений под именем ИИ-агента из каталога, и этот раздел доходит только до своего ИИ-агента.

- События хуков: `session_start`, `session_end`, `prompt_submit`, `before_tool`, `after_tool`, `after_tool_failure`, `stop`, `subagent_start`, `subagent_stop`, `notification`, `pre_compact`, `post_compact`.
- Инструменты: `shell`, `read`, `write`, `edit`, `glob`, `grep`, `list`, `web_fetch`, `web_search`, `task`, а также `mcp:<сервер>/<инструмент>` и `mcp:<сервер>/*`.
- `matcher` хука и `tools` субагента — это список имён из словаря или `"*"`, не regex. `timeout` хука задаётся в секундах.
- `~/.agents/hooks.json` содержит `"version": 1`, события ядра в `hooks` и разделы расширений на верхнем уровне (`"claude": {"hooks": {…}}`).
- Ядро субагента: `name`, `description`, `tools`, тело — инструкция. Ядро команды: `description`, `argument-hint`, тело с `$ARGUMENTS` и `$1…$9`. Расширения задаются вложенным ключом во frontmatter (`claude:`, `grok:`).
- В тексте команды хука каталог проекта обозначает `${AGENTS_PROJECT_DIR}`. `on` подставляет вместо неё родную переменную ИИ-агента, а если такой нет — `$PWD`.

**Перенос в agents.** Создание снимка ИИ-агента сначала переводит его собственные хуки, MCP-серверы, команды и субагентов в формат agents и переносит их в agents. Отдельной команды нет. Порядок такой: проверка секрета, затем снимок agents, затем перенос, затем снимок ИИ-агента. При обрыве обе папки возвращаются к состоянию до попытки. Перенесённый элемент у ИИ-агента становится записью, которую вписало подключение, или ссылкой, поэтому удаление из agents убирает его и у ИИ-агента и элемент не воскресает. Если имя уже занято в agents, побеждает agents, а собственный элемент не переносится. Хук или инструмент, который не раскладывается на словарь (regex `Ed.*`, `NotebookEdit`), переносится как есть в раздел расширений своего ИИ-агента. Навыки, машинные хуки и машинный MCP не переносятся. Вывод называет перенесённое и пропущенное. Каждый вид, который ИИ-агент получает переводом, у этого же ИИ-агента обязательно переносится и обратно.

**Независимость ИИ-агентов.** ИИ-агент получает элементы agents только своим подключением и никогда через файлы другого ИИ-агента. `on grok` выключает `[compat.claude]` и `[compat.cursor]` у видов, которые даёт agents, и запоминает это как свою запись, а `off` возвращает прежнее значение.

**Обёртка хука.** Каждый хук объявляет формат входа скрипта: `"input": "claude"`, `"agents"`, `"none"` и т. д. Перенос ставит формат ИИ-агента-источника. Если объявленный формат не совпадает с форматом работающего ИИ-агента, `on` вписывает вместо команды `agentsync hook --from <ИИ-агент> --to <формат> --event <событие> -- <команда>`. Обёртка переводит вход в объявленный формат, а ответ скрипта переводит обратно. Если формат совпадает или стоит `none`, обёртки нет. `agentsync` вызывается по имени через `PATH`, потому что абсолютный путь сделал бы хук машинным. Сбой обёртки на событиях `before_*` блокирует инструмент и называет причину, на остальных событиях пропускает. Поле, которое перевод не может заполнить, во входе отсутствует.

**Отказы.** Имя, которого нет в словаре, и `hooks.json` без `version` — это отказ подключения и отказ создания снимка agents, пояснение называет файл. Проверка идёт до изменения файлов. Если список после перевода для ИИ-агента пуст, элемент этому ИИ-агенту не достаётся: пустой список никогда не значит «все». Применение публикации, у которой хуки в формате Claude (публикация agents или записи `on` в карточке ИИ-агента), отказывает с пояснением.

Это решение меняет ADR 0037: формат agents больше не формат Claude Code, а вариант «первый `on` переносит собственные элементы в agents» принят в другой форме — перенос идёт при снимке, а не при `on`, и не трогает навыки.

## Уточнения при реализации

- Учёт записей помнит для каждой вписанной записи хука исходную запись agents, а метка публикации несёт эти пары. Применение карточки кладёт в agents исходную запись, а не обратный перевод, и разделы расширений других ИИ-агентов не теряются. Карточка несёт вместо переведённого субагента или команды исходный файл agents.
- Отказ применения из-за старого формата получает только публикация agents. Хуки в карточке ИИ-агента лежат в его родном формате, и старую карточку от новой по ним не отличить. Такие хуки переводятся обратно в формат agents с `input` ИИ-агента-источника.
- Субагенты и команды, которым нужен перевод, `on` пишет файлами и учитывает их как свои записи. Ссылка остаётся у файла без `tools` и без разделов расширений.
- `on grok` выключает в `[compat.*]` ключи `skills`, `mcps` и `hooks`. Ключ `agents` (чтение `CLAUDE.md`) остаётся: файла инструкций Grok из agents не получает.
- Обёртка передаёт команду в `sh` через окружение (`eval "$AGENTSYNC_HOOK_COMMAND"`): MSYS `sh` на Windows неверно читает аргумент `-c`, который начинается с кавычки.
- Если словарь не выражает часть инструментов собственного субагента, перенос кладёт в ядро выражаемую часть, а полный список — в раздел расширений. Пустое ядро `tools: []` ограничивает остальных ИИ-агентов, а не открывает им все инструменты.

## Considered Options

- Нейтральный формат только в публикации, на диске формат Claude. Отклонено: Claude остаётся главным, а переводов два вместо одного.
- Один собственный файл на всё, как `agentsync.toml` у dallay/agentsync. Отклонено: навыки и `AGENTS.md` уже читают десятки ИИ-агентов, и упаковка в свою схему их потеряла бы. У dallay перевод есть только у MCP.
- Имена событий и инструментов Claude как словарь agents: их уже понимают Claude, Grok, Codex и Copilot. Отклонено: формат снова стал бы форматом Claude.
- `matcher` как regex с переводом имён между `|`. Отклонено: `Ed.*` не переводится однозначно.
- Отдельная команда импорта. Отклонено: перенос должен идти без ручного шага.
- Перенос при `on`. Отклонено: перенос идёт при создании снимка.
- Перенос копией с учётом уже импортированного. Отклонено: на машине два состояния одного элемента.
- Grok получает хуки и MCP через файлы Claude. Отклонено: Grok без Claude остался бы без них.
- Читать старый формат Claude на лету. Отклонено: два формата на диске бессрочно.
- Не переводить вход скрипта хука. Отклонено: хук, который читает stdin, работал бы только у ИИ-агента-источника.
- Обёртка на каждом хуке. Отклонено: лишний процесс на каждый вызов инструмента там, где переводить нечего.
- Fail-open для всех событий. Отклонено: защитный хук молча пропускал бы опасную команду.

## Consequences

- `~/.agents/hooks.json` на машине автора сейчас в формате Claude. После выхода новой версии его надо переписать один раз вручную, иначе `on` откажет.
- Старые публикации с хуками в формате Claude больше не применяются, хотя их адрес остаётся.
- Если убрать `agentsync` из `PATH`, перестают работать все хуки с обёрткой. Вывод `on` предупреждает, если `agentsync` не найден.
- Ошибка перевода в обёртке блокирует инструмент на событиях `before_*`, пока её не исправят.
- `on grok` меняет `~/.grok/config.toml`: собственные навыки и хуки Claude, которых нет в agents, Grok больше не видит.
- Хуки подключаются только у ИИ-агентов, чей путь подтверждён их документацией или исходниками: Claude Code, Grok, Codex, Gemini CLI, Copilot. Cursor ждёт проверки `~/.cursor/hooks.json`.
- Команды получают Claude Code (ссылкой), Grok (читает `~/.agents/commands` сам) и Gemini CLI (перевод в TOML, `$ARGUMENTS` → `{{args}}`, команда с `$1…$9` пропускается). Cursor пропускает команды, пока синтаксис аргументов не подтверждён. У Codex команд нет с 0.117.
- Субагентов получают Claude Code, Grok, Gemini CLI, Cursor, Copilot (`*.agent.md`) и Codex (перевод в TOML). У Cursor и Codex нет списка инструментов. Субагент, у которого все инструменты только читают (`read`, `glob`, `grep`, `list`, `web_fetch`, `web_search`), получает у них `readonly: true` и `sandbox_mode = "read-only"`. Остальные субагенты с `tools`, отличным от `"*"`, этим двум ИИ-агентам не достаются.
- Точные соответствия событий, инструментов и полей входа для каждого ИИ-агента описаны в документации, а не здесь.
