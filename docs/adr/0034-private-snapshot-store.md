# У аккаунта частное хранилище снимков

У аккаунта на каждый ИИ-агент одно частное хранилище. Создание снимка явно добавляет неизменяемый снимок переносимой настройки и делает его текущим. Загрузка делает уже созданный снимок публикацией и не стирает прежние. Другой аккаунт хранилище не открывает и не применяет. На странице аккаунта его видит только вошедший владелец.

Перед применением чужой публикации текущая переносимая настройка записывается в хранилище применяющего, если в ней есть что записать. Публикацией этот снимок не становится. Откат сначала возвращает файлы к текущему снимку. Если файлы уже с ним совпадают, текущим становится предыдущий снимок. Снимок из хранилища не удаляется. Другая машина того же аккаунта меняет ИИ-агента только явным применением выбранного снимка.

В хранилище входит та же переносимая настройка, что и в публикацию. Секрет в названном файле останавливает создание снимка. Пустая переносимая настройка тоже. Учётные данные, машинный MCP и машинный хук не входят. Создание снимка, загрузка и снятие не требуют подтверждённой почты. Удаление аккаунта удаляет хранилище в облаке. Копия на диске машины остаётся и новому аккаунту не показывается.

Это решение заменяет ADR 0004 и ADR 0010. Правило ADR 0006, что применение не создаёт публикацию, остаётся. Меняется только место снимка перед применением: он лежит в хранилище.

## Considered Options

- Хранить в облаке только копию истории отката. Отклонено: правка без применения в облако не попадала бы.
- Удалять верхний снимок при откате. Отклонено: ранний снимок снова можно потерять одним откатом.
- Пускать секрет в частное хранилище. Отклонено: сервер хранил бы секрет, а поздняя загрузка могла бы его опубликовать.
- Ветки и слияние. Отклонено: у хранилища один текущий снимок, применение остаётся точной заменой.
