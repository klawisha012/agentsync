# `~/.agents/` — общая настройка, ИИ-агенты подключаются к нему ссылками

Общая настройка всех ИИ-агентов машины лежит в одном каталоге `~/.agents/` — agents. Команда `agentsync <ИИ-агент> on` подключает ИИ-агента: элементы agents появляются в его домашней папке ссылками. Команда `off` убирает эти ссылки. На странице аккаунта карточки по ИИ-агентам остаются, у agents своя карточка, свой снимок и своё хранилище.

Снимок ИИ-агента разворачивает ссылки на agents в копии, поэтому один навык может быть в двух карточках. Применение публикации agents точно заменяет agents. Применение публикации ИИ-агента кладёт её элементы в agents: одноимённые элементы заменяются целиком, новые добавляются, остальные остаются. Собственные файлы ИИ-агента, которые не элементы agents (`settings.json`, `keybindings.json`, свои навыки), ложатся в его домашнюю папку по тому же правилу: одноимённый файл заменяется целиком, остальные остаются. Элемент agents в снимке ИИ-агента узнаётся по месту, которое называет каталог ИИ-агентов. Записи MCP и плагинов, которые вписал `on`, по месту не отличить от собственных, поэтому снимок отмечает их отдельно и при применении они идут в agents, а не в `settings.json`. Публикации, загруженные до этого решения, разбираются так же, по месту: все их записи MCP и плагинов идут в agents. Затем этот ИИ-агент подключается. Перед изменением agents и домашняя папка ИИ-агента записываются в свои хранилища снимками перед применением.

Если имя элемента agents у ИИ-агента занято его собственной папкой или файлом, `on` сначала создаёт снимок ИИ-агента в его хранилище, затем ставит на это имя ссылку. Собственные элементы ИИ-агента с другими именами остаются у него и в agents не переходят.

MCP-сервер ссылкой не подключить: он лежит в общем файле ИИ-агента рядом с чужим состоянием, например в `~/.claude.json`. `on` вписывает серверы agents в этот файл в формате ИИ-агента, а машина помнит имена записей, которые вписала она. Повторный `on` убирает свою запись, которой в agents больше нет. Одноимённую чужую запись `on` заменяет после снимка ИИ-агента. `off` удаляет только свои записи. Чужие записи с другими именами и прочие ключи файла не меняются. Учёт записей — состояние машины, в снимок и публикацию он не входит.

У каждого вида элементов в agents один формат: навыки, субагенты, пользовательские команды, хуки и MCP. За основу взят формат Claude Code. Для каждой пары «ИИ-агент и вид» каталог ИИ-агентов называет способ: ссылка, когда формат совпадает; перевод в формат ИИ-агента с учётом своих записей, как у MCP; или «не поддерживается». Неподдерживаемый вид `on` пропускает и называет в выводе. Каталог растёт постепенно: сначала ссылки там, где формат совпадает, переводы добавляются позже.

Файл инструкций один: `~/.agents/AGENTS.md`. `on` ставит на него ссылку под именем, которое читает ИИ-агент: `CLAUDE.md`, `AGENTS.md`, `GEMINI.md`. Применение карточки ИИ-агента заменяет этот файл целиком, как любой элемент agents.

Плагин входит в agents только записью: источник маркетплейса, имя плагина и признак включения. `on` вписывает маркетплейс и включение в настройки ИИ-агента с учётом своих записей, как у MCP, а скачивает плагин сам ИИ-агент. ИИ-агент без плагинов этот вид пропускает.

Отдельного понятия «приёмник» нет. ИИ-агент — любая программа из каталога ИИ-агентов, который поставляется с сервисом. `on`, `off` и установка навыка работают с любым ИИ-агентом каталога, а карточка появляется только после публикации. Имя в команде — имя из каталога или его синоним: `claude` и `claude-code` называют одну программу. Опубликовать по-прежнему можно папку с любым именем.

Это решение заменяет ADR 0035 и меняет ADR 0002 и ADR 0005 для публикации ИИ-агента: применение больше не точная замена его домашней папки.

## Considered Options

- Источник — домашняя папка одного ИИ-агента, навыки разводятся приёмникам (ADR 0035). Отклонено: у каждого ИИ-агента своя копия общей настройки, и копии расходятся.
- Единица публикации — только agents, без карточек ИИ-агентов. Отклонено: на странице остаются карточки по ИИ-агентам.
- Ссылки на agents в снимок ИИ-агента не входят. Отклонено: карточка ИИ-агента показывает всё, что он видит.
- Применение публикации ИИ-агента точно заменяет agents. Отклонено: применение карточки Claude убрало бы навыки, которые видит только Grok.
- Отказ, если в agents уже есть одноимённый элемент. Отклонено: снимок перед применением уже защищает прежний элемент, отказ заставил бы удалять его вручную.
- Отказ `on`, если имя у ИИ-агента занято собственной папкой. Отклонено по той же причине: прежнюю папку возвращает откат.
- Оставить приёмник отдельным понятием и подключать только ИИ-агентов с карточкой. Отклонено: каталог приёмников в коде уже содержит `claude-code`, `codex` и `grok`, а Cursor без `on` не увидел бы agents.
- MCP как у dallay/agentsync в режиме `merge`: agents перекрывает одноимённые записи и ничего не удаляет. Отклонено: сервер, убранный из agents, оставался бы у ИИ-агента, а `off` его не убирал бы.
- MCP как у dallay/agentsync в режиме `overwrite`: раздел MCP становится точной копией agents. Отклонено: собственные серверы ИИ-агента пропадали бы.
- Подпапки agents по ИИ-агентам без перевода. Отклонено: хук для Claude никогда не дошёл бы до Gemini, общий agents для этих видов потерял бы смысл.
- В agents только виды с общим форматом, хуки и субагенты в карточках ИИ-агентов. Отклонено: цель agents — общие субагенты и хуки тоже.
- Отказ `on`, если ИИ-агент не понимает вид. Отклонено: тогда ИИ-агента без хуков нельзя подключить и к навыкам.
- Общий файл инструкций плюс личный файл ИИ-агента с импортом agents. Отклонено: импорт понимают не все ИИ-агенты. Личную надстройку можно добавить позже.
- Файл инструкций в карточке каждого ИИ-агента. Отклонено: правила расходятся между ИИ-агентами.
- Подпапка agents на каждого ИИ-агента для его собственных файлов. Отклонено: agents перестал бы быть общей настройкой.
- Не применять собственные файлы ИИ-агента. Отклонено: модель, тема и разрешения автора тоже часть карточки.
- Применять старые публикации прежней точной заменой. Отклонено: два применения в коде, а после применения у ИИ-агента обычные папки вместо ссылок.
- Скрыть старые публикации. Отклонено: адрес публикации постоянный.
- Распаковать плагин в навыки и хуки agents. Отклонено: обновление плагина agents не догонит, происхождение элементов теряется, имена разных авторов сталкиваются.
- Оставить плагины в карточке ИИ-агента. Отклонено: agents должен нести всю общую настройку.
- Первый `on` переносит все собственные элементы ИИ-агента в agents. Отклонено: личный навык одного ИИ-агента молча стал бы виден всем.

## Consequences

- Применение публикации ИИ-агента включает подключение. Кнопка чужой публикации меняет agents, а значит и все подключённые ИИ-агенты машины.
- Создание снимка ИИ-агента должно читать ссылку на каталог. Сейчас `readTree` на ней падает.
- Поиск ИИ-агентов сейчас пропускает `.agents`, а agents нужна своя карточка.
- Секрет в MCP agents решает ADR 0038.
- Перевод хуков неполный: событие, которого у ИИ-агента нет, этому ИИ-агенту не достаётся.
- Сейчас `portablePath` не берёт в снимок каталоги `agents` и `commands`.
- Применение чужой карточки ИИ-агента заменяет общие правила всех подключённых ИИ-агентов. Вернуть прежние можно только откатом agents.
- `settings.json` заменяется целиком: личный `statusLine` и разрешения применяющего уходят в снимок перед применением. Слияние по ключам можно добавить позже.
- В старой публикации собственные MCP-серверы автора тоже уходят в agents и становятся видны всем подключённым ИИ-агентам применяющего.
- ИИ-агент без плагинов не видит навыков из плагина.
- Сейчас `privatePath` отбрасывает `marketplace-cache`, но не `marketplaces`: клоны маркетплейсов Claude (около 20 МБ) попадают в снимок.
- Имя из поиска ИИ-агентов (`claude` из папки `.claude`) и slug каталога (`claude-code`) сейчас различаются, каталогу нужны синонимы.
