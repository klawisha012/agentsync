# Разводка показывает навыки приёмникам общей записью

Разводка делает все внешние навыки из домашней папки одного ИИ-агента видимыми в глобальном каталоге названных приёмников на той же машине. У каждого навыка своя общая запись с каноном, не копия. Публикация, хранилище и разовое применение не меняются: применение разводку не включает, аккаунт ей не нужен. Человек называет приёмников при включении и при выключении, машина набор не хранит.

## Considered Options

- Заменить модель живыми ссылками из каталога проекта, как у локальной синхронизации конфигов. Отклонено: публикация и разовое применение остаются работой сервиса.
- Копировать навыки в приёмник. Отклонено: это установка навыка, после неё папки расходятся.
- Сделать общей записью весь каталог навыков. Отклонено: набор фиксируется моментом действия, а установка должна класть свою папку рядом.
- Включать разводку применением. Отклонено: кнопка чужой публикации меняла бы несколько программ.
- Заменять папку приёмника, если имя занято. Отклонено: у приёмника нет снимка, чужие файлы пропали бы.
- Показывать вложенный SKILL.md отдельным именем. Отклонено: общая запись не раскладывается в соседа, навык был бы виден дважды.
- Требовать аккаунт. Отклонено: хранилище и публикацию разводка не трогает.

## Consequences

- Если разводка уже включена, применение и откат канона видны приёмнику, хотя ссылки создало не применение.
- Повторное включение одно на всех названных приёмников. Конфликт по имени возвращает их к состоянию до попытки, поэтому навык, удалённый из канона, до чистого повтора остаётся виден.
- MCP, хуки, плагины, правила, тема, конфиг и коннектор в разводку не входят. Позже вид можно добавить только вместе со своим местом у приёмника. Машинный MCP и машинный хук не войдут и тогда.
- Секрет в файле навыка останавливает разводку так же, как запись. Пояснение называет файл и не содержит значение.
- Если ссылку создать нельзя, разводка не выполнена. Тихой копии вместо общей записи нет.
