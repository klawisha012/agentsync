# Секрет MCP хранится переменной, значение остаётся на машине

В переносимом файле вместо значения секрета стоит переменная секрета, например `${GITHUB_TOKEN}`. Значение лежит в окружении или в `~/.agents/.env`. Файл `.env` в снимок не входит. Переменная секрета секретом не считается: снимок agents с ней создаётся, и сервер публикуется. Получатель кладёт своё значение у себя.

`on` пишет переменную в синтаксисе ИИ-агента. Если ИИ-агент переменные не раскрывает, `on` подставляет значение с машины в его файл настроек.

Машинный MCP решается по серверу, а не по файлу. Машинным остаётся только сервер с абсолютным путём. Заголовок `Authorization` с переменной сервер машинным не делает. Значение секрета прямо в файле по-прежнему останавливает создание снимка, как в ADR 0013.

Это решение меняет определение машинного MCP из ADR 0005: секретный заголовок и токен в окружении больше не делают сервер машинным.

## Considered Options

- Сервер с секретом считать машинным MCP. Отклонено: такой сервер не публикуется, и получатель о нём не узнаёт.
- Оставить как было: значение останавливает снимок, `authorization` убирает файл MCP целиком. Отклонено: в agents один файл MCP, и один сервер с заголовком убрал бы из публикации все серверы.

## Consequences

- Для каждого ИИ-агента каталог должен знать, раскрывает ли он переменные: Claude Code раскрывает `${VAR}` в `.mcp.json`, у Codex есть `env_vars` и `bearer_token_env_var`. Остальных надо проверить.
- После подстановки файл настроек ИИ-агента содержит значение секрета. В снимок agents этот файл не входит, а снимок ИИ-агента остановит та же проверка на секрет.
- Сейчас правило машинного MCP в `portable.go` решает по файлу и ищет слово `authorization`. Код нужно перевести на решение по серверу.
