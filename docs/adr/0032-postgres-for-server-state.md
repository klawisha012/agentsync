# Состояние сервера хранится в Postgres

Сервер держит аккаунты, публикации, лайки и просмотры в памяти процесса, и перезапуск их стирает. Это состояние переезжает в Postgres до тикета предпросмотра (#8). Учётные данные, сессии, кэши, логи, память, история диалогов, машинный MCP и машинный хук остаются на машине. Хранилище снимков лежит в Postgres, как в ADR 0034.

В Postgres лежат аккаунт (почта, хеш пароля, имя, подтверждение почты), сессия на 14 суток, ссылка из письма на сутки, привязка машины (идентификатор компьютера, хост, слушатель, токен локального агента), хранилище (снимки ИИ-агента и текущая метка), публикация (постоянный адрес, ИИ-агент, номер, время, сжатое тело), лайк и просмотр вместе с тем, кто страницу уже открыл. На компьютере остаются копия хранилища, учётные данные ИИ-агента, его сессии, кэши, логи, память, история диалогов, машинный MCP, машинный хук и уже применённая настройка.

Тесты вызывают тот же HTTP. Сервер под ними говорит с Postgres, который тест поднимает в Docker. Compose поднимает тот же Postgres для обычного запуска. Схему сервер накатывает при старте. Второй копии состояния в памяти нет.

## Considered Options

- Оставить память процесса. Отклонено: перезапуск стирает аккаунты, публикации, лайки, просмотры, сессии и уже выданные ссылки.
- Оставить снимки только на компьютере. Это отклонение ADR 0010 снято ADR 0034: снимки лежат в Postgres, копия на диске остаётся.
- Держать для тестов второе хранилище в памяти. Отклонено: два пути разъедутся.
- Дописать предпросмотр и применение на памяти, потом перенести. Отклонено: это вторая переделка.
