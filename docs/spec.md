# AgentSync

Спецификация сервиса, в котором снимок ИИ-агента лежит в частном хранилище, загрузка делает снимок публикацией, а другой аккаунт разово применяет её у себя.

Словарь: `CONTEXT.md`. Решения: `docs/adr/`.

Сейчас в репозитории каркас: сервер отвечает на проверку живости, сайт показывает, доступен ли сервер. Аккаунтов, публикаций и локального агента ещё нет.

## Problem Statement

Человек собирает поведение разных ИИ-агентов: навыки, правила, плагины, хуки и конфиг. Grok, Agents и Claude здесь только знакомые примеры, не полный список. Перенести это другому человеку сейчас значит копировать домашние папки ИИ-агентов целиком. В тех же домашних папках ИИ-агентов лежат вход в ИИ-агент, сессии, кэши и привязка к конкретной машине. Полная копия либо сбрасывает вход у того, кто принимает настройку, либо уносит чужой вход в облако.

Нужен способ опубликовать только переносимую настройку, посмотреть её до применения и один раз заменить ею своего ИИ-агента, не трогая свой вход и не подписываясь на чужие будущие правки.

## Solution

У человека есть аккаунт с публичным именем и страница. Он явно записывает одного ИИ-агента в частное хранилище. Загрузка отмечает уже записанный снимок публикацией. Новая загрузка не стирает старые. Кнопка ИИ-агента применяет последнюю. Другой аккаунт хранилище не видит.

Другой человек открывает страницу без входа, смотрит предпросмотр и применяет публикацию. Локальный агент перед этим записывает снимок в хранилище применяющего и точно заменяет переносимую настройку. Учётные данные, машинный MCP, машинные хуки и поставка продукта остаются. Страница применяющего не меняется. Вторая машина того же аккаунта сама настройку не меняет.

Запись, загрузка, снятие, откат и применение своей публикации доступны после входа. Подтверждение почты эти действия не закрывает.

## User Stories

### Аккаунт

1. As a новый человек, I want to создать аккаунт почтой и паролем и сразу выбрать имя, so that у меня были страница и вход ещё до подтверждения письма.
2. As a владелец аккаунта, I want to входить до подтверждения почты, so that я мог подтвердить машину, записать снимок, откатиться и применить свою публикацию, не дожидаясь письма.
3. As a владелец аккаунта, I want to подтвердить почту по письму, so that адрес был отмечен подтверждённым. Загрузка, снятие и запись от письма не зависят.
4. As a владелец аккаунта, I want to получить письмо для смены забытого пароля, so that я снова вошёл в тот же аккаунт.
5. As a гость, I want to не видеть почту на странице аккаунта, so that публичное имя не раскрывало адрес.
6. As a владелец аккаунта, I want to сменить имя после входа, so that страница открывалась по новому имени, а адреса публикаций оставались прежними.
7. As a человек, выбирающий имя, I want to чтобы `Alice` и `alice` были одним именем, so that поиск без учёта регистра не показывал две неразличимые страницы.
8. As a человек, выбирающий имя, I want to использовать буквы любого алфавита, цифры и дефис не по краям, от 3 до 32 знаков, so that адрес страницы оставался читаемым.
9. As a человек, выбирающий имя, I want to чтобы похожие буквы разных алфавитов оставались разными именами, so that правило уникальности не угадывало за меня чужой алфавит.
10. As a человек, выбирающий имя, I want to чтобы имена страниц самого сайта были заняты, so that я не перекрыл служебный адрес.
11. As a владелец аккаунта, I want to удалить аккаунт только после повторного ввода пароля, so that одно случайное нажатие не сняло все публикации.
12. As a владелец аккаунта, I want to увидеть пояснение при неверном пароле удаления, so that я понял, почему аккаунт остался.
13. As a владелец аккаунта, I want to удалить аккаунт без подтверждённой почты, so that свежий аккаунт можно было убрать сразу.
14. As a гость, I want to чтобы после удаления страница исчезла из списка, имя освободилось, а все публикации были сняты, so that удалённого человека больше нельзя было открыть и применить.
15. As a человек, которого лайкал удалённый аккаунт, I want to чтобы этот лайк снялся, so that счётчик не хранил отметку несуществующего аккаунта.
16. As a человек, создавший аккаунт заново с той же почтой или тем же именем, I want to получить новый пустой аккаунт, so that старые публикации и хранилище ко мне не вернулись.

### Машина

17. As a человек, I want to открыть одну инструкцию установки, so that ИИ-агент на компьютере поставил локальный агент и довёл его до подтверждения машины.
18. As a владелец аккаунта, I want to подтвердить машину на сайте после входа, so that локальный агент вошёл в мой аккаунт, а пароль не попал в инструкцию.
19. As a владелец аккаунта без подтверждённой почты, I want to подтвердить и снять машину, so that привязка компьютера не ждала письма.
20. As a владелец аккаунта, I want to снять подтверждение машины, so that локальный агент перестал входить в аккаунт, а хранилище осталось.
21. As a второй человек на том же компьютере, I want to подтвердить машину своим аккаунтом, so that у компьютера оставался один аккаунт за раз.
22. As a прежний владелец компьютера, I want to чтобы моё хранилище не показывалось новому аккаунту, so that частные снимки не открывались следующему человеку.
23. As a прежний владелец компьютера, I want to снова увидеть своё хранилище, когда компьютер опять подтверждён мной, so that смена аккаунта его не стёрла.

### Загрузка и публикация

24. As a владелец аккаунта, I want to явно загрузить один снимок своего хранилища, so that этот снимок стал одной новой публикацией.
25. As a владелец аккаунта, I want to чтобы сохранение файла в ИИ-агенте само ничего не записывало и не публиковало, so that хранилище и страница менялись только от явной записи и явной загрузки.
26. As a владелец аккаунта, I want to загрузить каждого ИИ-агента по отдельности, so that кнопка одного не меняла остальных.
27. As a гость, I want to видеть новую публикацию сразу, so that мне не нужно было ждать проверки сервисом.
28. As a гость, I want to открыть и прежнюю публикацию того же ИИ-агента, so that новая загрузка не стирала снимок прошлого момента.
29. As a гость, I want to чтобы у публикации был постоянный адрес, so that смена имени автора не ломала уже переданную ссылку.
30. As a гость, I want to чтобы кнопка ИИ-агента применяла последнюю неснятую публикацию, so that со страницы применялось актуальное состояние.
31. As a автор, I want to получить отказ, если у ИИ-агента нет переносимой настройки или этого ИИ-агента на компьютере нет, so that пустая публикация не стёрла чужого ИИ-агента. Пояснение называет эту причину.
32. As a автор, I want to получить отказ, если в переносимом файле есть секрет, so that ключ не стал публичным. Пояснение называет файл и не показывает значение секрета.
33. As a автор, I want to загрузить ИИ-агента любого размера, so that большое дерево навыков не отрезалось пределом. Тело хранится сжатым.
34. As a автор, I want to чтобы учётные данные, сессии, кэши, логи, lock-файлы, память ИИ-агента и история диалогов не вошли в публикацию, so that мой вход оставался на машине.
35. As a автор, I want to чтобы машинный MCP не вошёл в публикацию, so that абсолютный путь, секретный заголовок и токен окружения не уехали чужому человеку.
36. As a автор, I want to чтобы хук с абсолютным путём и скрипт, на который он ссылается, не вошли в публикацию, so that чужая машина не получила команду в моего ИИ-агента.
37. As a автор, I want to чтобы хук без абсолютного пути вошёл в переносимую настройку, so that поведение хука переносилось вместе с остальным конфигом.
38. As a автор, I want to чтобы навык с абсолютным путём внутри текста остался навыком, so that машинными считались только MCP и хук, а не любой файл.
39. As a автор, I want to чтобы поставка продукта и кэши не входили в публикацию, so that я публиковал свою настройку, а не файлы установки.
40. As a автор, I want to открыть инструкцию загрузки, где назван каждый ИИ-агент, so that ИИ-агент на компьютере записал названного в хранилище и загрузил новый снимок через локальный агент.
41. As a автор без локального агента, I want to чтобы инструкция загрузки перешла к инструкции установки и сама не изменяла ИИ-агента, so that загрузка шла через одну программу.
42. As a человек, у которого в браузере и на машине разные аккаунты, I want to получить пояснение и не загрузить ИИ-агента, so that файлы одного компьютера не стали публикацией другого аккаунта.

### Предпросмотр и снятие

43. As a гость, I want to открыть предпросмотр без входа, so that я увидел файлы публикации до применения.
44. As a гость, I want to чтобы предпросмотр совпадал с тем, что применение изменит в переносимой настройке, so that машинный MCP и машинные хуки в нём не обещались.
45. As a автор, I want to снять одну публикацию без локального агента, so that её больше нельзя было открыть и применить заново.
46. As a человек, уже применивший снятую публикацию, I want to чтобы мой ИИ-агент не изменился из-за снятия, so that снятие останавливало только новую раздачу.
47. As a гость, I want to чтобы кнопка ИИ-агента после снятия последней публикации перешла на предыдущую оставшуюся, so that у ИИ-агента по-прежнему было что применить.
48. As a гость, I want to чтобы у ИИ-агента без оставшихся публикаций не было кнопки применения, so that нажимать было не на что.
49. As a автор без подтверждённой почты, I want to снять публикацию, so that письмо не держало снятие.

### Применение

50. As a гость, I want to применить чужую публикацию без входа, so that локальный агент этого компьютера заменил переносимую настройку одного ИИ-агента.
51. As a применяющий, I want to чтобы навыки, правила, плагины и разделяемые ключи конфига стали такими, как в публикации, so that ИИ-агент совпал с тем, что я видел в предпросмотре.
52. As a применяющий, I want to чтобы мой файл, которого нет в публикации, ушёл из ИИ-агента и остался только в снимке перед применением, so that применение заменяло настройку, а не сливало две.
53. As a применяющий, I want to сохранить свои учётные данные, машинный MCP, машинные хуки и поставку, so that вход и привязка к моей машине не слетели.
54. As a применяющий, I want to чтобы применение не создавало публикацию и не меняло мою страницу, so that чужая настройка не публиковалась под моим именем.
55. As a применяющий, I want to чтобы поздние публикации автора сами не приезжали, so that кнопка оставалась разовым действием.
56. As a владелец аккаунта, I want to применить свою публикацию только после входа в браузере, so that без входа применялась только чужая.
57. As a человек с инструкцией своей публикации и без входа в браузере, I want to получить пояснение и остановку, so that правило входа было одним и для кнопки, и для инструкции.
58. As a человек с инструкцией чужой публикации, I want to чтобы ИИ-агент применил её через локальный агент, so that запись в ИИ-агента делала та же программа, что и кнопка.
59. As a человек без локального агента, I want to чтобы кнопка применения отсутствовала, а инструкция перешла к установке и сама не изменяла ИИ-агента, so that браузер не заменял домашнюю папку ИИ-агента.
60. As a человек, у которого в браузере чужой аккаунт, а локальный агент компьютера свой, I want to всё равно применить чужую публикацию на этот компьютер, so that совпадение аккаунтов не требовалось для чужого применения.
61. As a человек без этого ИИ-агента на компьютере, I want to чтобы применение создало переносимые файлы и не добавило пустой снимок в хранилище, so that на новой машине настройка появилась, а вход я сделал сам.

## Implementation Decisions

Проверка шва, на котором это будет тестироваться, вынесена в Testing Decisions. Здесь только принятое поведение.

- Сервер хранит аккаунты, имена, подтверждение почты, публикации, лайки и просмотры. Сайт и локальный агент говорят с этим сервером. Браузер ИИ-агента не изменяет.
- ИИ-агентом может быть любой именованный агент, не только Grok, Agents и Claude. У каждого свои публикации. Кнопка ИИ-агента применяет последнюю неснятую. Если оставшихся нет, кнопки нет.
- Запись одного ИИ-агента добавляет один снимок в его хранилище. Загрузка этого снимка создаёт одну публикацию. Тело — переносимая настройка, сжатая zstd на максимальном уровне. Предпросмотр и применение работают с файлами, секрет ищется до сжатия. Предела размера и числа снимков нет.
- В переносимую настройку входят конфиг, хуки без абсолютного пути, тема, включённые плагины, правила, навыки, плагины и MCP без машинной привязки. Не входят учётные данные, сессии, кэши, логи, lock-файлы, память, история диалогов, поставка, машинный MCP и машинный хук вместе с его скриптом.
- Публикация неизменна и имеет постоянный адрес. Снятие прячет её от предпросмотра и новых применений. Уже применённые машины не меняются.
- Применение — точная замена переносимой настройки одного ИИ-агента. Лишние переносимые файлы применяющего уходят в снимок перед применением. Учётные данные, машинный MCP, машинные хуки и поставка на машине остаются. Успешное применение дописывает снимок в хранилище применяющего и не создаёт публикацию. Обрыв возвращает ИИ-агента к состоянию до попытки и снимок попытки не сохраняет.
- Хранилище одно на пару «аккаунт и ИИ-агент». Снимки неизменяемы и не удаляются откатом. Чужой аккаунт его не видит. Другая машина того же аккаунта меняет файлы только явным применением снимка. Откат не меняет публикации. Отдельной инструкции отката нет.
- Чужое применение доступно без входа и при несовпадении аккаунта браузера с аккаунтом локального агента. Своё применение, загрузка, снятие и откат требуют входа. Подтверждение почты их не закрывает. Снятие не требует локального агента.
- Инструкция установки одна на сайт. Инструкция применения своя у публикации. Инструкция загрузки одна и называет каждого ИИ-агента отдельно. Если локального агента нет, инструкции применения и загрузки переходят к установке и сами не изменяют ИИ-агента.
- Список аккаунтов открыт всем. Поиск — вхождение в имя, без регистра, живой список с первого символа. Пустая строка показывает весь список. Сортировка по умолчанию: лайки, затем просмотры, затем имя. Дополнительно: просмотры, имя, время последней публикации. Аккаунт без публикации в сортировке по времени последний.
- Лайк: один на пару «вошедший аккаунт — чужая страница», повтор снимает, свою страницу нельзя. Просмотр: владелец не считается; браузер без входа даёт не больше одного; вход привязывает этот просмотр к аккаунту; другой компьютер того же аккаунта второй не добавляет; предпросмотр публикации просмотром страницы не является.
- У компьютера один аккаунт за раз. Новое подтверждение сменяет прежнее, копии хранилищ на диске остаются раздельными. Снятие машины оставляет хранилище. Удаление аккаунта снимает публикации, удаляет хранилище в облаке, освобождает имя, убирает страницу из списка и снимает лайки этого аккаунта. Повторный пароль обязателен. Новый вход с той же почтой — новый аккаунт. Копия на диске ему не показывается.
- Каркас уже поднимает сервер и сайт через Docker Compose. Этот каркас не реализует аккаунты и публикации.
- Пояснение показывается человеку, когда действие не выполнено: нет переносимой настройки, секрет в названном файле, нет входа, применение оборвалось, пароль удаления неверен. Значение секрета в пояснение не входит.

## Testing Decisions

Один шов. Тест снаружи создаёт аккаунт, загружает ИИ-агента через ту же команду, которой пользуется локальный агент, и проверяет ответ сервера и временный каталог ИИ-агента. Сайт считается клиентом этого сервера: отдельный шов браузера не нужен, пока страница только показывает то, что сервер уже отдал.

Хороший тест проверяет наблюдаемое поведение: какой снимок записан, какая публикация появилась, что человек видит в предпросмотре, какие файлы оказались в ИИ-агенте, какие файлы входа и машинные хуки остались, что хранилище дописало снимок или откат вернул файлы, какое пояснение пришло при отказе. Тест не проверяет сжатие как алгоритм и не заглядывает в приватные функции разбора конфига.

На этом шве должны быть видны точная замена, отказ пустой загрузки, отказ из-за секрета, сохранение машинного MCP и машинного хука, обрыв применения, один просмотр на человека, лайк и его снятие, снятие публикации и удаление аккаунта.

Уже есть тест проверки живости сервера. Новые тесты следуют тому же приёму: вызвать сервис снаружи и прочитать ответ, а для ИИ-агента — прочитать временный каталог после команды локального агента.

## Out of Scope

- Подписка на автора и самопроизвольная доставка хранилища на другую машину. Применение разовое.
- Ветки и слияние хранилища. У хранилища одна текущая метка.
- Проверка содержимого публикации сверх секрета, пустой переносимой настройки и машинных MCP и хуков.
- Поиск по тексту файлов.
- Предел размера публикации и предел числа публикаций.
- Лайк отдельной публикации, просмотр предпросмотра как просмотр страницы, лайк без входа, лайк своей страницы.
- Инструкция отката и публичный адрес хранилища.
- Повторный пароль при смене имени.
- Слияние похожих букв разных алфавитов в одно имя.
- Групповые аккаунты и жалоба на публикацию.
- Перенос уже применённой настройки при снятии публикации или удалении аккаунта.

## Further Notes

Тело публикации сжимается zstd на максимальном уровне, потому что размера нет, а распаковка при применении должна оставаться быстрой. Brotli рассматривался как тот же класс и не выбран форматом хранимого тела.

Локальный агент — единственная программа, которая читает и пишет ИИ-агента. Кнопка, инструкция применения и инструкция загрузки сходятся в него.
